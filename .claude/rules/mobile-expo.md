# Mobile: Expo (React Native)

Specs: `docs/tech/00-tech-stack.md` § 4, ADR-002, ADR-015, ADR-016, `docs/ux/01-information-architecture-and-flows.md`. See the `mobile-screen` and `offline-mutation` skills.

## Platform

- Expo with **development builds** (not Expo Go), New Architecture and Hermes. Continuous Native Generation: `ios/` and `android/` are generated by prebuild and never edited or committed. Native configuration goes through `app.config.ts` and config plugins.
- **Expo Router**, file-based. Navigation differs for player-only users and users with any staff role (UX § 3.1–3.2).
- Deep links: universal links (iOS) and verified App Links (Android) for `/e/…`, `/j/…`, `/c/…` must open the matching screen (NFR-COMP-03).
- EAS Build, Submit and Update with channels `preview`, `staging`, `production` and the `fingerprint` runtime-version policy. OTA updates may only change JS and assets; anything native needs a store build.
- Native dependencies are declared in `apps/mobile/package.json` (autolinking only sees them there), installed with `npx expo install` so versions match the SDK, and kept at one version across the workspace.
- Keep `babel.config.js` and `metro.config.js`: NativeWind needs them.
- Task skills: `expo-dev-client` (dev builds), `eas-update` (OTA), `expo-upgrade` (SDK upgrades), `expo-animation` (motion and gestures), `expo-design-system` (tokens, primitives, native tells), `react-native-skills` (lists, animation, UI patterns), `mobile-performance` (speed and size).
- Read the docs for the installed SDK: `https://docs.expo.dev/llms.txt` and `docs.expo.dev/versions/v<major>.0.0/`. The installed version wins over memory.
- `create-expo-app` writes `.claude/settings.json` (it turns on the full Expo plugin, including skills that conflict with this stack, such as `expo-ui` and `expo-data-fetching`) and an `AGENTS.md`. At TECH-01, delete that settings file and don't import that `AGENTS.md`; this rule and the vendored Expo skills replace them.
- Expo SDK 58 ships **Gesture Handler 3** (hook API: `usePanGesture` style, `onActivate` / `onDeactivate`). `@gorhom/bottom-sheet` 5.2.14 predates it, so confirm the pair works before building sheets on it.

## Data and offline

- TanStack Query with the cache persisted to **react-native-mmkv**. Offline reads cover the agenda (next 14 days), event details and availability, published plans, active routines and nutrition plans, and own stats (NFR-OFF-02).
- **Offline writes** for RSVP, bulk RSVP, roll call, wellness check-ins and routine logs are paused mutations persisted and resumed on reconnect, each with an `Idempotency-Key` created when the user acts (NFR-OFF-01). Use the `offline-mutation` skill.
- The UI always shows sync state: queued, syncing, or failed with retry. Forms keep drafts until submitted (NFR-OFF-03).
- **Zustand** only for local UI state (selected club and category, UI preferences). Never for server data.
- Refresh tokens in **expo-secure-store** (Keychain / Keystore). Never in MMKV, AsyncStorage or logs (NFR-SEC-11).

## UI and performance

- **NativeWind** classes with the shared preset, on top of the project's own primitives. No inline style objects with hard-coded values.
- Target low and mid-range Android: cold start to Home ≤ 3 s (NFR-PERF-03), download ≤ 40 MB (NFR-DATA-03).
- Long lists (roll call, directory, agenda) use **@shopify/flash-list**, never `ScrollView` + `map`. FlashList v2 needs no `estimatedItemSize`; use `getItemType` for mixed rows, and never put `entering` animations on rows.
- Reanimated 4 with `react-native-worklets`: `scheduleOnRN` (not the removed `runOnJS`), shared values read and written with `.get()` / `.set()`, never `setState` in gesture or scroll handlers. Animate `transform` and `opacity` only.
- Create `Intl` formatters once (module scope or memoized), never during render.
- Images through **expo-image** with resized variants, never full resolution in lists (NFR-DATA-01). Video through **expo-video**, **never autoplay on mobile data** (NFR-DATA-02).
- Gestures and animation with Reanimated and Gesture Handler; sheets with `@gorhom/bottom-sheet`; charts with victory-native; body map with react-native-svg.
- Media: compress on device before upload (expo-image-manipulator, react-native-compressor), then upload to the presigned URL with progress and retry.

## Push

`expo-notifications` with notification categories and actions (Voy / No voy) for RSVP pushes. Register the device token with `PUT /v1/me/devices/{deviceId}`. Tapping a notification deep-links to its screen.

## Accessibility

Every interactive element has an accessibility label and role; dynamic type up to 200% without losing function; touch targets ≥ 44×44 pt (NFR-A11Y-02); high-contrast styles on field screens.

## i18n and observability

FormatJS (`react-intl`) with `expo-localization`, catalogs from `packages/i18n` (Intl polyfills where Hermes needs them). `@sentry/react-native` and `posthog-react-native` with the same privacy filters as web.
